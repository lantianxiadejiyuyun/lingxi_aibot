# 开发指南

[返回首页](../README.md) · [部署说明](部署.md) · [使用指南](使用指南.md)

面向修改代码和本地调试。正式运行请使用 [Docker 部署](部署.md#首次安装)。

## 本地启动

准备 Python 3.11+ 和一个专用 MySQL 数据库，字符集使用 `utf8mb4`。Node.js 仅用于运行前端回归测试。

### 1. 安装依赖

在项目根目录执行，按系统任选一组。

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Linux / macOS：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

已有 `.env` 时跳过复制，保留现有配置。

### 2. 填写配置

编辑根目录 `.env`：

- `MYSQL_HOST / MYSQL_PORT / MYSQL_USER / MYSQL_PASSWORD / MYSQL_DB`：填写开发数据库连接。
- `SESSION_COOKIE_SECURE=0`：本地 HTTP 登录需要此值；正式 HTTPS 部署使用 `1`。
- `SECRET_KEY`：填写随机长字符串。
- `SCHEDULER_ENABLED=0`：仅调试网页时可关闭定时任务；测试提醒功能时设为 `1`。

聊天模型可在启动后登录「设置 → 模型与人设」配置。连接本机或局域网模型服务时，需要明确设置 `ALLOW_LOCAL_PROVIDERS=1`。

### 3. 初始化并启动

Windows PowerShell：

```powershell
.\.venv\Scripts\python -m flask --app run init-db
.\.venv\Scripts\python run.py
```

Linux / macOS：

```bash
.venv/bin/python -m flask --app run init-db
.venv/bin/python run.py
```

默认打开 `http://127.0.0.1:5000`。`ADMIN_PASSWORD` 留空时，初始化命令生成随机管理员密码并在终端显示一次。也可通过 `/setup` 完成安装，向导使用 `data/setup_token.txt` 中的令牌保护写操作。

开发入口默认不启用调试器。可用 `HOST`、`PORT` 修改监听地址和端口；`FLASK_DEBUG=1` 仅在回环地址启用调试器。

## 运行测试

以下命令中的 `python` 指项目虚拟环境的解释器。可激活虚拟环境，或替换为上面的完整路径。

优先运行离线回归，无需真实数据库、模型密钥或外部网络：

```bash
python -m unittest discover -s scripts/tests -p "test_*.py"
node --test scripts/tests/test_admin_entry.js
```

Python 测试使用临时配置与内存 SQLite，覆盖会话控制、压缩、用户隔离、飞书连接生命周期、网页链接、持久化、日程提醒等。Node 测试验证带后台入口前缀时的前端请求行为。

`scripts/` 根目录还保留功能测试与真实接口测试，例如 `smoke_test.py`、`test_pages_ai_e2e.py`、`test_images_ai_e2e.py`。它们可能读写当前配置的数据库或调用付费接口。运行前先阅读脚本，在专用测试环境中按改动范围选择执行。

## 常用管理命令

```bash
# 幂等建表、补充兼容字段和默认任务
python -m flask --app run init-db

# 重设管理员密码，随机密码会显示一次
python -m flask --app run reset-admin-password --username admin

# 立即备份、重建语义检索索引
python -m flask --app run backup-now
python -m flask --app run reindex
```

需要清空开发库时，先运行 `python -m flask --app run reset-db` 查看待删除表；添加 `--yes` 才会删除当前数据库的全部数据表。确认正在使用可丢弃的开发库后再执行。

## 代码在哪里

```text
app/
├── ai/             模型接口、对话执行、提示词、工具注册与工具实现
├── blueprints/     网页、API、安装向导和飞书路由
├── models/         数据模型
├── services/       业务逻辑、消息渠道、独立网页服务
├── scheduler.py    定时任务和动作注册
├── templates/      Jinja2 页面模板
└── static/         CSS、JavaScript
scripts/tests/      离线回归测试
docs/               使用、部署和架构文档
run.py              本地开发入口
wsgi.py             生产 WSGI 入口
```

应用使用单进程、多线程运行：生产入口是 `wsgi:app`，Docker 使用 Gunicorn 单 worker，普通部署可用 Waitress。多 worker 会重复启动进程内的定时任务、飞书连接和独立网页服务。

## 扩展功能

- **AI 工具：** 在 `app/ai/tools/` 增加模块，以 `@register_tool` 注册，参照相邻工具定义参数和结果。服务层保持用户数据作用域，避免跨用户读写。
- **定时动作：** 用 `app.scheduler.register_action` 注册动作，由定时任务配置调用。涉及日期时遵循现有时区转换；数据库时间按项目约定存储为 UTC。
- **通知渠道：** 在 `app/services/channels/` 新建模块，继承 `BaseChannel` 并使用 `@register_channel`。实现 `name`、`display_name`、`configured` 和 `send`；发送失败抛出异常，通知中心会记录原因。配置项需同步接入设置页面。
- **前端请求：** 使用共享的 `window.api` 和 `window.streamSSE`，让请求自动带上后台入口前缀；修改时同时检查普通路径和 `ADMIN_ENTRY` 场景。

改动后运行相关回归，并更新对应的使用或部署说明。模型、表结构和路由的详细参考见 [PROJECT.md](PROJECT.md)；其中的历史规划和测试数量以当前代码及测试输出为准。

## 生成发行包

```bash
python scripts/pack_release.py
```

结果位于 `release/lingxi/` 和相应 zip 文件；加 `--no-zip` 只生成目录。发行内容由脚本生成，请修改源文件后重新打包，不要直接改生成目录。详见 [发行包说明](../release/README.md)。
