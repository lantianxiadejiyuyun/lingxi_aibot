# 飞书私聊

Rust 后端负责身份绑定、会话、工具、主库记忆与投递记录。单独的 Node 24 容器使用飞书官方 `@larksuiteoapi/node-sdk` 1.76.0 建立长连接，不需要公网回调地址。原来的飞书 Webhook 和应用通知渠道仍可使用。

## 配置

1. 飞书开发者后台启用自建应用机器人。申请接收单聊消息 `im:message.p2p_msg:readonly` 和以应用身份发送消息 `im:message:send_as_bot` 权限；将自己的账号加入应用可用范围，发布并安装/更新应用。
2. 事件与回调中选择长连接，订阅 `im.message.receive_v1`。新应用可能需要先启动桥接服务建立连接，再保存订阅方式。
3. 灵犀“设置 → 通知渠道 → 飞书机器人（应用）”填写 App ID 和 App Secret。只使用私聊时，通知接收人可留空。
4. 在下方“飞书私聊”开启接入，生成专用桥接密钥。将其填入部署目录的 `.env`（限制文件权限，不入版本控制）：

   ```dotenv
   LINGXI_FEISHU_BRIDGE_TOKEN=页面生成的专用密钥
   LINGXI_FEISHU_IMAGE=lingxi-feishu:2.0.0
   ```

5. 构建并启动桥接容器（保留部署原有的其他 Compose 文件参数）：

   ```sh
   docker compose -f docker-compose.yml -f docker-compose.feishu.yml build feishu-bridge
   docker compose -f docker-compose.yml -f docker-compose.feishu.yml up -d feishu-bridge
   ```

6. 页面显示长连接正常后，生成绑定码并私聊发给机器人。绑定码十分钟有效，仅使用一次。此后直接发送文字即可。

每个飞书应用只启动一个桥接实例。同一应用的多个长连接由平台分配事件，不能当作广播使用。密钥轮换后需要更新容器环境并重建容器。App ID / App Secret 改变后需要重新绑定主人。

## 行为和排查

- 只处理绑定主人的私聊。群聊、机器人消息、未绑定用户不会调用模型或访问个人工具。图片、语音、文件会提示改发文字。
- 主人的飞书对话及记忆位于主 SQLite 数据库；每个账号有一条独立飞书会话。解绑保留已有会话，重绑后新建会话。
- SDK 回调在返回前将消息原子写入持久卷并同步磁盘；后端接收成功后才删除暂存文件。后台任务按账号串行执行，message_id 唯一约束去重。最多暂存 1,000 条，后台最多待处理 100 条；超过 24 小时的事件不再执行。
- 发送前重新检查开关和绑定，并记录发送意图。模型失败或外部投递结果不明时不自动重放，避免重复工具操作和重复消息。页面“最近的接收记录”可查看状态，完整回复保存在会话中。
- “检查应用连接”仅验证凭据与机器人启用状态，不发送测试消息，也不能证明事件订阅、应用可用范围及全部消息权限都正确。实际收发需绑定后发送一条文字验证。
- 长连接正常但没有接收记录：检查事件订阅、接收单聊权限及已发布版本。接收记录处理失败：检查模型配置、发送权限与机器人可用范围。
- 容器健康检查确认进程能访问后端；页面另行显示真实 WebSocket 状态。桥接日志只记录状态，不输出 SDK 的签名 URL、密钥或消息内容。
- 清空上下文时应停掉接入，清理 `feishu_events`（连带 `feishu_parts`）、对应任务和会话，清空桥接持久卷的 `inbox`，使旧消息不会在清空后恢复。备份必须保留 `master.key` 才能解密配置。

官方参考：[Node SDK](https://github.com/larksuite/node-sdk)、[飞书事件接收](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)。
