# 主动陪伴与 AstrBot

灵犀负责 AI 对话、记忆、日程和待办；AstrBot 负责连接聊天平台。已有的模型、人设和账号数据继续在灵犀里管理，不需要另外接入 Harness。

## 开启主动陪伴

已有实例先按[升级步骤](部署.md#升级)更新程序并执行 `python -m flask init-db`，补齐陪伴状态、活动记录、AstrBot 绑定和投递队列表，再重启应用。新功能默认关闭，升级后不会自动推送。

打开「主动陪伴」，开启总开关，设置活动时段、免打扰时间、每日条数和推送渠道，再保存。

- 时间按当前账号的时区计算，免打扰时段优先，日程忙碌时暂缓。开始与结束相同时，活动时段表示全天，免打扰时段表示关闭。
- 每日条数是上限，不会为了凑数发送。刚聊完会暂缓，长时间没有互动会降频。
- 可以填几个感兴趣的话题。消息沿用当前账号的模型、人设和记忆。
- 每次活动可以在「最近的小记」中查看；已生成的消息保存到跨日连续的「灵犀日常」会话，可随时跳回继续聊。
- 内容可结合真实的近期聊天、待办和未来日程；不会把已经结束的安排说成接下来要发生的事。
- 保存设置不会立即发送消息。关闭开关后停止后续主动活动。

勾选「B 站新发现」后，灵犀可以根据兴趣搜索公开资料，并附上真实视频链接。这一版依据搜索结果中的标题与摘要选题，**不等于完整观看视频**，也不会向 B 站发评论、私信或代替你点赞。

## 连接 AstrBot

1. 部署 AstrBot，并安装本项目随附的灵犀桥接插件（下方 Docker 配置已挂载插件）。
2. 在灵犀「设置 → 账号 → 外部应用接入」生成账号 API Token。完整 Token 只显示一次。
3. 从对应平台私聊机器人，发送 `/lingxi 身份`。在 AstrBot 插件配置中填写返回的私聊身份、灵犀 API 地址和该 Token。Token 只保存在插件后台，不要发送到聊天窗口。
4. 在同一私聊发送 `/lingxi 绑定`。绑定成功后，文字消息交给灵犀处理；可以用 `/lingxi 状态` 查询。
5. 回到灵犀「主动陪伴」确认绑定状态，并选择 AstrBot 推送渠道。

API 地址使用 AstrBot 容器能够访问的地址，并包含 `/api/v1`。例如管理入口为 `https://example.com/lingxi/` 时，通常填写 `https://example.com/lingxi/api/v1`。Docker 容器内的 `127.0.0.1` 指向容器自身；同一 Compose 网络中请使用灵犀服务名和内部端口。

「主动陪伴」页可以解除 AstrBot 绑定。撤销或重新生成账号 API Token 后，旧 Token 会失效，需要在插件中更新。

当前桥接支持私聊文字及灵犀命令；图片、语音、文件仍可通过灵犀原有渠道使用。平台本身需要允许机器人主动发消息；AstrBot 的 QQ 官方适配器不支持本插件所用的主动发送方式。

## Docker 启动

项目提供 [`docker-compose.astrbot.yml`](../docker-compose.astrbot.yml)，默认使用 AstrBot `v4.29.1`，插件位于 [`integrations/astrbot`](../integrations/astrbot)。从仓库根目录执行：

```bash
docker compose -f docker-compose.astrbot.yml --profile astrbot up -d
```

管理页默认只监听本机 `127.0.0.1:6185`。在服务器部署时可用 SSH 转发访问；需要局域网访问时设置 `ASTRBOT_BIND_IP` 为服务器的局域网地址。

如果灵犀使用项目主 Compose 部署，可将 AstrBot 加入同一个 `aibot` 网络：

```bash
docker compose -f docker-compose.yml -f docker-compose.astrbot.yml --profile astrbot up -d astrbot
```

此时插件的 API 地址通常为 `http://app:8000/lingxi/api/v1`，其中 `lingxi` 替换为实际管理入口。AstrBot 数据保存在 `data/astrbot`，插件目录只读挂载。插件配置支持多组账号，每组明确指定一个允许接入的私聊身份。

## 常见情况

**已开启，但没有马上收到消息**：保存不会立即发送；先检查当前时间、免打扰、最近聊天冷却、每日额度和模型配置。没有值得分享的新内容时，也会保持安静。

**站内有消息，聊天平台没收到**：检查所选渠道与绑定状态；到通知中心查看发送结果。AstrBot 需要持续运行才能把排队的消息送回平台。

**小记显示“正在判断”或“送达状态未知”**：前者表示正在准备内容；后者表示发送过程中断、无法确认是否送达，为避免重复不会自动补发。判断中断和保持安静也会计入当天判断次数。

**想让说话方式更自然**：在「模型与人设」调整称呼、口吻和简洁程度。主动陪伴会沿用这些设置，无需再写一份人设。
