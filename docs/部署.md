# 部署指南

**飞牛 fnOS / Linux 首次安装，推荐 Docker。** 只启动灵犀和 MySQL，不需要先准备 Python、数据库、域名或证书。

已有实例请直接看 [升级](#升级)，保留现有配置。宝塔、systemd、外部 MySQL 和 Caddy 见 [部署参考](部署参考.md)。

| 用途 | 默认地址 |
|---|---|
| 管理后台 | `http://服务器IP:8000/login` |
| AI 生成的公开网页 | `http://服务器IP:8080/webs/html/<slug>` |
| MySQL | 仅供容器内部访问，不映射宿主机端口 |

## 首次安装

以下用于**全新安装**。在服务器的管理员终端执行；飞牛可用管理员账号 SSH 登录后运行 `sudo -i`。后续命令均在项目根目录执行。

### 1. 准备 Docker 和项目

先在飞牛应用中心安装 Docker，或在 Linux 安装 Docker Engine 与 Compose v2。确认 Compose 支持 `--wait`：

```bash
docker compose version
docker compose up --help
```

进入准备存放项目的目录，再下载代码：

```bash
git clone https://github.com/lantianxiadejiyuyun/lingxi_aibot.git
cd lingxi_aibot
```

没有 Git 也可以下载当前仓库 ZIP 并解压。使用仓库根目录中的文件，`deploy/` 是旧版快照。

### 2. 只填写两个密码

```bash
cp -n .env.docker.example .env
```

用文本编辑器打开 `.env`，填写两项**不同的长密码**，建议使用字母和数字，避免 `$` 等字符被 Compose 当作变量：

```dotenv
MYSQL_PASSWORD=填写应用数据库密码
MYSQL_ROOT_PASSWORD=填写数据库管理密码
```

其他配置已适配 Docker：数据库主机为 `db`、HTTP 登录可用、网页端口为 `8080`。`SECRET_KEY` 留空，程序会首次生成并持久保存。AI Key 可以登录后再填。

模板中的 `COMPOSE_FILE=docker-compose.quickstart.yml` 会让后续 `docker compose` 命令自动使用快速部署配置。**已有 `.env` 时不要重新套用此模板。**

### 3. 准备数据目录

```bash
mkdir -p data/backups data/images
chown 1000:1000 data data/backups data/images .env
chmod 600 .env
```

镜像里的应用以用户 `1000` 运行，需要读取初始配置、写入 `data/`。上面仅调整这些新建数据目录和配置文件，也适用于发行包预建的空目录。

### 4. 建库，再启动应用

按顺序执行，上一条成功后再继续：

```bash
# 结果应只有 app、db；密码未填时会直接提示
docker compose config --services

docker compose build app
docker compose up -d --wait db
docker compose run --rm --no-deps app python -m flask init-db
docker compose up -d --wait app
```

初始化会创建数据库表、管理员和内置任务，并在终端打印一次随机管理员密码。请保存这个密码。先初始化再启动应用，可让提醒调度器正常启动。

### 5. 登录并填写模型

打开 `http://服务器IP:8000/login`，使用 `admin` 和刚生成的密码登录。

1. 「设置 → 账号」修改管理员密码。
2. 「设置 → 模型与人设」填写接口地址、API Key 和模型；每位用户使用自己的配置。
3. 「设置 → 网页站点」填写实际访问地址。仅局域网使用可填 `http://服务器IP:8080`，公网分享见下节。

检查运行状态：

```bash
docker compose ps
```

`app` 和 `db` 应显示 `healthy`。再登录并发送一条 AI 消息；`/healthz` 只验证应用存活，不代表数据库、模型或飞书都已连通。

## 公开网页

后台端口 `8000` 用于登录管理，网页端口 `8080` 用于访问公开网页和公开图片。

**局域网使用：** 在「设置 → 网页站点 → 公网访问地址」填 `http://服务器IP:8080`。该字段也接受局域网根地址，避免链接显示成容器内部 IP。

**线上分享：** 先配通端口转发或 HTTPS 反向代理，再把外部入口填入同一字段。例如：

| 项目 | 示例 |
|---|---|
| 应用内部网页端口 | `8080` |
| GOST 目标地址 | `127.0.0.1:8080`（客户端为 host 网络时） |
| 公网入口 | `http://203.0.113.10:30079` |
| 「公网访问地址」 | `http://203.0.113.10:30079` |

`203.0.113.10` 仅是示例，请替换为自己的地址。AI 生成网页后会返回该根地址下的 `/webs/html/<slug>`。填写完整 `http://` 或 `https://` 根地址，不带页面路径。

公网访问地址只决定**链接写什么**，不会自动创建转发或开放端口。填写外部端口时，内部网页端口仍保留 `8080`。私有网页和图片继续要求登录。

<a id="65-docker-与网页端口"></a>
### GOST 访问本机端口

| GOST 网络模式 | 目标地址怎样填 |
|---|---|
| Linux `host` | `127.0.0.1:8080` 指向宿主机 |
| Docker `bridge` | `127.0.0.1` 指向 GOST 容器自己，应改为可达的宿主机地址 |

快速配置默认发布到 `0.0.0.0`，host 网络的 GOST 可用 `127.0.0.1:8080`。如果你把端口仅绑定到局域网 IP，则需要使用该 IP，或另加回环绑定。`localhost` 可能解析为 IPv6 `::1`；只绑定 IPv4 时请明确使用 `127.0.0.1`。需要双回环配置时看 [详细示例](部署参考.md#gost-客户端无法访问本机端口)。

测试要分两段：先从 GOST 容器中访问目标地址，再用公网地址打开同一个公开网页。

## 飞书机器人

内网和飞牛部署通常使用**官方 SDK 长连接**：服务主动连接飞书，收消息无需开放回调端口。

1. 在飞书开放平台创建自建应用并开启机器人能力。
2. 事件订阅选择长连接，订阅 `im.message.receive_v1`；开通单聊消息读取、机器人发送消息等所需权限，并发布应用配置。
3. 在「设置 → 飞书」填 App ID、App Secret，接收方式选 SDK。
4. 为灵犀账号绑定飞书用户身份，私聊机器人发一条消息验证。

网页与飞书共用 `/model`、`/think`、`/auto`、`/compact` 等命令，见 [使用指南](使用指南.md#模型与上下文)。收消息成功后，分享网页还需按上一节配置可达的入口。

已有公网 HTTPS 回调的环境也可选择 `callback`，回调路径为 `/feishu/event`；应用配置与开放平台的接收方式应一致。

## 配置放在哪里

| 位置 | 用途 | 什么时候改 |
|---|---|---|
| 根 `.env` | Compose 选择、端口映射、MySQL 首次初始化、应用首启配置 | 首次安装；修改 Docker 映射 |
| `data/.env` | 应用实际运行配置 | 已安装后的数据库、Cookie 等配置 |
| 网页「设置」 | 模型、飞书、公开地址等可视化设置 | 日常使用优先在这里修改 |
| `data/` 与 `mysql_data` 卷 | 图片、备份、运行配置与数据库数据 | 持久保留 |

根 `.env` 只在首次导入，之后不会覆盖 `data/.env`。更改根文件中的 MySQL 密码，不会修改已初始化的数据库账号密码。

端口被占用时，可在根 `.env` 添加 `APP_PORT=18000` 或 `WEB_PORT=18080`，再运行 `docker compose up -d --no-deps app`。它们只改变宿主机端口，内部仍为 `8000/8080`；记得同步后台访问地址、网页访问地址及转发目标。

使用 HTTPS 反代后台后，将 `data/.env` 的 `SESSION_COOKIE_SECURE` 改为 `1` 并重建应用；HTTP 访问保持 `0`。Nginx 反代 AI 对话需要关闭缓冲，配置见 [部署参考](部署参考.md#55-可选nginx-反代--sse)。

## 升级

**沿用当前实例的编排文件、项目名、挂载目录和数据库卷。** 快速模板适用于新装，不用于覆盖已有部署；旧实例继续用它原来的命令。以下适用于本指南安装的实例。

先在「设置 → 备份」备份数据库并下载，再单独备份 `.env`、`data/` 和实际 Compose 配置到项目外的私有目录。

```bash
# Git 安装可拉取更新；ZIP 安装则替换代码，保留配置和数据
git pull --ff-only

docker compose build app
docker compose run --rm --no-deps app python -m flask init-db
docker compose up -d --no-deps --wait app
docker compose ps
```

`init-db` 用于补表、补字段，保留已有数据；失败时先处理报错，再替换运行中的应用。升级不需要重建数据库服务，也不要删除 `mysql_data` 卷。

升级后检查登录、AI 对话、飞书连接和公开网页。更换了网页配置时，局域网与公网分别打开验证。

## 常用命令

以下仍在项目根目录执行：

```bash
# 最近的应用日志
docker compose logs --tail=100 app

# 只重启应用
docker compose restart app

# 重置管理员密码（随机生成并显示一次）
docker compose exec app python -m flask reset-admin-password --username admin

# 立即备份数据库
docker compose exec app python -m flask backup-now
```

## 常见问题

| 现象 | 先检查 |
|---|---|
| 提示必须设置 MySQL 密码 | 根 `.env` 的两项密码是否都已填写 |
| 8000 / 8080 被占用 | 在根 `.env` 改 `APP_PORT` / `WEB_PORT`，重建 app |
| `data/.env` 无法写入 | 新装目录是否由用户 `1000` 可写；现有目录先核对属主再修改 |
| MySQL 连不上 | 自带库主机应为 `db`；查看 `docker compose logs --tail=100 db` |
| 登录后回到登录页 | HTTP 访问时 `data/.env` 的 `SESSION_COOKIE_SECURE` 应为 `0` |
| 飞书不回复 | 检查长连接状态、事件/权限是否发布、发送者是否绑定 |
| 局域网能访问，公网不通 | 检查隧道目标 IP/端口及防火墙；不能只修改分享地址 |
| 重启后提醒不运行 | 确认 `init-db` 成功，再重启 app；保持单 worker |
| 出现示例 Caddy / 提示域名错误 | 确认根 `.env` 选择了 `docker-compose.quickstart.yml` |

想使用已有 MySQL、宝塔、systemd 或自定义 HTTPS，继续阅读 [部署参考](部署参考.md)。
