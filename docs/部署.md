# 灵犀（Lingxi）部署教程

适用版本：**v1.2**（Flask 3 + MySQL + waitress / gunicorn）。本文按**当前代码**写，覆盖：

- 宝塔面板
- 普通 Linux 服务器（systemd + 可选 Nginx）
- Docker
- MySQL 建库与连库
- 网页 HTTP 端口、飞书接入、备份、安全等**上线必须知道**的事项

相关文件：[.env.example](../.env.example) · [docker-compose.yml](../docker-compose.yml) · [Dockerfile](../Dockerfile) · [wsgi.py](../wsgi.py)

## 0. 先选部署方式

| 方式 | 适合 | 入口 |
|---|---|---|
| **宝塔面板** | 已装宝塔、习惯图形界面 | [第四节](#四宝塔面板部署) |
| **普通 Linux 服务器** | 无面板的 Ubuntu/Debian 云主机 | [第五节](#五普通-linux-服务器部署) |
| **Docker** | 干净机器、想一条命令跑起来 | [第六节](#六docker-部署) |
| 本机开发 | Windows / macOS 调试 | 仓库根 [README.md](../README.md) 的「快速开始」 |

三种生产方式**共用**同一套规则：MySQL 必须先建好、应用**单进程**、公开网页推荐只开 HTTP 端口。请先读完第一节再动手。

架构（生产）：

```
浏览器 ──► 后台（waitress/gunicorn :8000，可选 Nginx/Caddy 反代）
              │
              ├─► MySQL（utf8mb4）
              ├─► 定时任务 APScheduler（必须跟应用同进程，只能 1 个 worker）
              └─► 网页站点（可选独立端口 PAGE_PORT，纯 HTTP，不配证书）
```

## 一、上线必须知道（先读完再部署）

### 1.1 只能单进程，禁止多 worker

定时任务跑在 **Flask 进程内部**（APScheduler）。`gunicorn -w 4`、开两个 Python 项目、再起一份 Docker 容器，都会导致：

- 早报 / 提醒 / 备份 **重复执行**
- 飞书 SDK 长连接 **重复收消息**

正确启动：

| 环境 | 命令 |
|---|---|
| 宝塔 / Windows / 普通 Linux | `waitress-serve --host=127.0.0.1 --port=8000 --threads=8 --channel-timeout=3600 wsgi:app` |
| Docker（镜像默认） | `gunicorn -w 1 --threads 8 -b 0.0.0.0:8000 --timeout 300 wsgi:app` |

**不要用 uvicorn**。本项目是 WSGI，uvicorn 是 ASGI，会报：

`Flask.__call__() missing 1 required positional argument: 'start_response'`

开发用 `python run.py`（默认 `0.0.0.0:5000`）即可，**不要**把 `run.py` 当生产入口。

### 1.2 Python 版本

用 **3.11 或 3.12**。不要用 3.14（依赖尚未普遍支持）。Docker 镜像是 `python:3.11-slim`。

### 1.3 没有 `.env` 也能启动

首次启动若没有 `.env`，程序会从 `.env.example` 自动生成，并把弱 `SECRET_KEY` 换成随机值。数据库连不上时**不会崩**，浏览器会跳到 **`/setup` 安装向导**。

安装向导需要粘贴服务器上的安装令牌：`data/setup_token.txt`（进程第一次打开 `/setup` 时自动生成）。这是为了防止公网窗口期被别人抢注管理员。

命令行初始化与网页向导等效、都是幂等的：

```bash
python -m flask init-db          # 建表 + 补列 + 管理员 + 13 个内置定时任务
```

`ADMIN_USERNAME` / `ADMIN_PASSWORD` 只在**库里还没有用户**时生效；默认 `admin` / `admin123`（或 `.env` 里改过的值）。**登录后立刻在「设置 → 账号」改密码。**

### 1.4 Cookie 与 HTTP / HTTPS

| 访问方式 | `.env` |
|---|---|
| 局域网 / 公网 IP + HTTP 端口（推荐网页站点这种） | `SESSION_COOKIE_SECURE=0` |
| 已用 Nginx/Caddy 上 HTTPS | `SESSION_COOKIE_SECURE=1` |

设为 `1` 却用 HTTP 打开后台，会出现：**登录成功立刻被踢回登录页**。

### 1.5 公开网页：只开端口，不必配证书

「设置 → 网页站点」填 **PAGE_PORT**（如 `8080`），保存后进程在 `0.0.0.0:8080` 再监听一个**迷你 HTTP 站点**，只提供公开网页和公开图片：

- 地址：`http://<PAGE_HOST 或本机 IPv4>:8080/<slug>`
- **不走 HTTPS、不要求域名**
- 该端口**没有**后台登录，不能当管理入口
- 不能与后台端口相同（生产后台一般是 8000，网页不要填 8000）

云厂商安全组 / 宝塔防火墙 **必须放行该端口**，否则外网打不开生成的网页。飞书里点开网页链接，还需要服务器有**公网 IPv4**（没有公网 IP 时飞书打不开构建页，与收消息方式无关）。

`ADMIN_DOMAIN` / `PAGE_DOMAIN` 是可选高级项：只有你已经有 Nginx/Caddy 证书时才填。

### 1.6 飞书两种收消息方式

| 方式 | 配置 | 公网要求 |
|---|---|---|
| HTTP 回调 `callback` | 开放平台事件订阅 URL：`https://你的后台域名/feishu/event` | 必须公网 HTTPS（国内通常要备案） |
| 官方 SDK 长连接 `sdk` | 开放平台选「使用长连接接收事件」；后台「设置 → 飞书」选 SDK | **收消息不需要公网**；**网页链接仍要公网 IPv4** |

不要两种同时开。SDK 模式切换后需**重启应用**才能稳定生效（长连接客户端没有干净的 stop）。

### 1.7 反代必须关掉 SSE 缓冲

AI 对话是 SSE 流式。Nginx / 宝塔反代若缓冲，表现为：**转圈很久，然后一大段一起出来**。必须：

```nginx
proxy_buffering off;
proxy_cache off;
proxy_http_version 1.1;
proxy_set_header Connection "";
proxy_read_timeout 300s;
```

### 1.8 持久化目录

| 路径 | 内容 | 部署时 |
|---|---|---|
| `.env` | 密钥与 MySQL | **不要**覆盖、不要提交 git |
| `data/backups/` | 每日/手动 JSON.gz 备份 | 要持久化 |
| `data/images/` | 生成的图片 | 要持久化 |
| `data/setup_token.txt` | 仅安装窗口期 | 初始化完成后可删 |
| `data/logs/` | 若你把日志指到这里 | 建议做 logrotate |

Docker 必须把 `./data` **和** `./.env` 挂进容器，否则安装向导改的数据库密码会在重建镜像后丢失。

### 1.9 改了哪些必须重启

| 改什么 | 要不要重启 |
|---|---|
| 「设置」里的模型 / 人设 / 渠道 / 简报 / 备份 / **网页端口** | 否（端口会热启停） |
| `.env` 的 `SECRET_KEY`、`ADMIN_ENTRY`、数据库账号、飞书 SDK 模式 | **要** |
| 更新代码、`requirements.txt` | 要（先 `pip install` 再 `flask init-db` 再重启） |

## 三、MySQL：建库、授权、连上灵犀

应用**不会**替你创建数据库账号。向导和 `flask init-db` 都只连接一个**已经存在**的库。

统一建议：

- 库名 `ai_bot`，用户 `ai_bot`（不要用 root 跑应用）
- 字符集 `utf8mb4`，排序 `utf8mb4_unicode_ci`
- 能本机连就不要对公网开放 3306

### 3.1 宝塔里建库

1. 软件商店安装 **MySQL 5.7 或 8.0**，并确认已启动
2. 「数据库 → 添加数据库」
   - 数据库名：`ai_bot`
   - 用户名：`ai_bot`，密码用强密码
   - 访问权限：**本地服务器**（应用与 MySQL 同一台时）
   - 编码：**utf8mb4**
3. 把主机/端口/用户/密码/库名记下来，填进 `.env` 或安装向导

若应用跑在 **Docker 容器**、MySQL 在宝塔宿主上：访问权限不要只选「本地服务器」，改为允许 Docker 网桥（常见 `172.17.0.1`）或「所有人」（仍建议防火墙挡住公网 3306）。`.env` 里 `MYSQL_HOST` 填 `host.docker.internal`（本仓库 compose 已加 `extra_hosts`）或宿主机内网 IP。

### 3.2 命令行建库（普通服务器 / 自装 MySQL）

```bash
sudo mysql -u root -p
```

```sql
CREATE DATABASE ai_bot CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'ai_bot'@'localhost' IDENTIFIED BY '换成强密码';
GRANT ALL PRIVILEGES ON ai_bot.* TO 'ai_bot'@'localhost';
-- 若应用在另一台机器 / Docker 网段：
-- CREATE USER 'ai_bot'@'172.17.0.%' IDENTIFIED BY '换成强密码';
-- GRANT ALL PRIVILEGES ON ai_bot.* TO 'ai_bot'@'172.17.0.%';
FLUSH PRIVILEGES;
```

测连通（在**跑应用的那台机器**上）：

```bash
mysql -h 127.0.0.1 -P 3306 -u ai_bot -p ai_bot -e "SELECT 1"
```

### 3.3 Docker 自带 MySQL

见 [6.3](#63-方式-b容器内-mysql推荐干净机器一条龙)。`.env` 必须 `MYSQL_HOST=db`（服务名），密码与 compose 里创建的用户一致。

### 3.4 `.env` 里这五项必须对

```ini
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=ai_bot
MYSQL_PASSWORD=你的密码
MYSQL_DB=ai_bot
```

| 场景 | `MYSQL_HOST` 填什么 |
|---|---|
| 应用与 MySQL 同一台（宝塔 / systemd） | `127.0.0.1` |
| 应用 Docker，MySQL 在宿主机 | `host.docker.internal` 或 `172.17.0.1` |
| 应用与 MySQL 都在同一 compose 网络 | `db`（服务名，**不要**填 127.0.0.1） |
| 远程云数据库 | 内网地址或厂商给的 hostname（并放行来源 IP） |

密码里有 `@ # : / %` 等特殊字符也可以，程序会做 URL 编码。不要把密码两边加上引号写进 `.env`（`dotenv` 会把引号当成密码的一部分）。

改 `.env` 里的数据库配置后需要**重启进程**才会重连；**安装向导里保存数据库**会热重建引擎，不必重启。

### 3.5 连不上时对照错误码

向导「测试连接」和日志里的 PyMySQL 错误：

| 现象 / 错误码 | 原因 | 处理 |
|---|---|---|
| `2003` 无法连接 | MySQL 没启动、地址端口错、防火墙、绑在 `skip-networking` | `systemctl status mysql`；宝塔看数据库状态；核端口 |
| `1045` Access denied | 用户名或密码错，或 `'用户'@'来源主机'` 不匹配 | 重新授权；Docker 场景给 `172.17.%` / `%` |
| `1049` Unknown database | 库还没建 | 先 `CREATE DATABASE` |
| `1044` 无权访问该库 | 用户存在但没 GRANT 这个库 | `GRANT ALL ON ai_bot.*` |
| 向导保存成功但后台 500 | 热切换偶发，重启一次应用 | 重启 waitress/gunicorn |
| 中文乱码 | 库不是 utf8mb4 | 重建库或 `ALTER DATABASE ... utf8mb4` |

SQLAlchemy 连接串由程序生成，**不要**自己拼 `SQLALCHEMY_DATABASE_URI`。

### 3.6 初始化表结构

连上之后二选一：

**A. 网页** — 打开 `/setup` → 粘贴 `data/setup_token.txt` → ① 填库并测试 → ② 初始化 → ③ 建管理员 → ④ 可选填 LLM Key。

**B. 命令行**（在项目根，虚拟环境已激活）：

```bash
export FLASK_APP=wsgi:app     # Windows PowerShell: $env:FLASK_APP = "wsgi:app"
python -m flask init-db
```

成功会看到建表、补列、管理员、内置任务的日志。可重复执行。之后升级代码也再跑一次，用来补新列。

## 四、宝塔面板部署

适用：云服务器已装 [宝塔](https://www.bt.cn)，用面板的 Nginx / MySQL / Supervisor（或 Python 项目管理器）。**不用 Docker、不用 uvicorn。**

推荐拓扑：

```
后台（可走宝塔 Nginx 80/443 反代）──► 127.0.0.1:8000 waitress
公开网页 ──► 服务器公网 IP:PAGE_PORT（如 8080，纯 HTTP）
MySQL ──► 127.0.0.1:3306（宝塔安装，不对公网）
```

没有域名也可以：把 waitress 改成 `--host=0.0.0.0 --port=8000`，防火墙放行 8000 和网页端口，`.env` 里 `SESSION_COOKIE_SECURE=0`。

### 4.1 面板里先装软件

软件商店：

- Nginx
- MySQL 5.7 / 8.0
- **Supervisor 管理器**（推荐）或 **Python 项目管理器**
- Python 3.11 或 3.12（项目管理器自带也可）

安全组 / 宝塔「安全」：放行 `22`、面板端口；若用反代再放行 `80/443`；网页站点再放行 `PAGE_PORT`（如 8080）。**不要**把 MySQL 3306 对公网放行。后台若只监听 `127.0.0.1:8000`，8000 也不用放行。

### 4.2 上传代码

把项目放到 `/www/wwwroot/aibot/`（或 `/www/aibot/`），保证这一层能看到 `wsgi.py`：

```
/www/wwwroot/aibot/
├── app/
├── wsgi.py
├── run.py
├── requirements.txt
├── .env.example
└── data/          # 运行后自动出现 backups/ images/
```

```bash
chown -R www:www /www/wwwroot/aibot
```

不要把本机的 `.venv`、`__pycache__` 一起上传。

### 4.3 虚拟环境与依赖

```bash
cd /www/wwwroot/aibot
# Python 路径以「Python 项目 → 版本管理」为准
/www/server/pyporject_evn/versions/3.12.7/bin/python3 -m venv .venv
.venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

`waitress` 已写在 `requirements.txt` 里，装完即可用。

### 4.4 配置 `.env`

```bash
cp .env.example .env
# 用宝塔文件管理器编辑 .env
```

最少改这些：

```ini
SECRET_KEY=        # 可留空占位，启动时会自动换成随机串；建议自己：openssl rand -hex 32
SESSION_COOKIE_SECURE=0   # 先 HTTP；若后台已上 HTTPS 再改 1

MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=ai_bot
MYSQL_PASSWORD=宝塔里那个密码
MYSQL_DB=ai_bot

LLM_API_KEY=sk-你的DeepSeek或兼容Key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat

ADMIN_USERNAME=admin
ADMIN_PASSWORD=首次初始化才用，登录后立刻改

PAGE_PORT=8080
PAGE_HOST=           # 留空则自动用本机局域网/公网 IPv4
# ADMIN_DOMAIN=      # 有 HTTPS 域名再填
# PAGE_DOMAIN=
```

其余图片 / 视觉 / TTS / 嵌入 / 飞书都可以先空着，登录后在「设置」里配。

### 4.5 建库并初始化

按 [3.1](#31-宝塔里建库) 建好 `ai_bot` 后：

```bash
cd /www/wwwroot/aibot
.venv/bin/python -m flask --app wsgi init-db
```

也可以先启动应用，浏览器打开 `http://服务器IP:8000/setup`（需 waitress 监听 `0.0.0.0` 或已做反代）走向导。令牌在：

```bash
cat /www/wwwroot/aibot/data/setup_token.txt
```

### 4.6 用 Supervisor 启动（推荐）

宝塔 → 软件商店 → Supervisor 管理器 → 添加守护进程：

| 项 | 值 |
|---|---|
| 名称 | `aibot` |
| 启动用户 | `www` |
| 运行目录 | `/www/wwwroot/aibot` |
| 启动命令 | 见下 |

后台只给本机 Nginx 反代时（8000 不对公网）：

```text
/www/wwwroot/aibot/.venv/bin/waitress-serve --host=127.0.0.1 --port=8000 --threads=8 --channel-timeout=3600 wsgi:app
```

没有 Nginx、直接 IP 访问后台时，把 `--host=127.0.0.1` 改成 `--host=0.0.0.0`。

日志目录先建好：`mkdir -p /www/wwwroot/aibot/data/logs`

启动后：

```bash
curl -I http://127.0.0.1:8000/login
```

应返回 200/302。未初始化时会 302 到 `/setup`。

**Python 项目管理器**也可以：框架选 Flask，启动方式选**命令行/自定义**，命令同上。不要用面板默认的 uvicorn 模板。

### 4.7 （可选）Nginx 反代后台

有域名、想给后台上 HTTPS 时：

1. 「网站 → 添加站点」，域名如 `admin.你的域名`，纯静态、不创建 FTP/数据库
2. SSL → Let's Encrypt
3. 反向代理 → 目标 `http://127.0.0.1:8000`，发送域名 `$host`
4. 打开「反向代理 → 配置文件」，在 `location` 里补上 [1.7](#17-反代必须关掉-sse-缓冲) 那几行
5. `.env`：`ADMIN_DOMAIN=admin.你的域名`，`SESSION_COOKIE_SECURE=1`，然后重启应用

公开网页**不必**再配一个 web 域名；继续用 `PAGE_PORT` 即可。若坚持 `https://web.域名/<slug>`，同样反代到 8000，并在设置里填 `PAGE_DOMAIN`。

### 4.8 放行网页端口

宝塔「安全」放行 `8080`（或你填的端口），云厂商安全组同样放行。保存「设置 → 网页站点」后，日志应有：

`网页站点 HTTP 已监听 0.0.0.0:8080`

浏览器打开 `http://服务器公网IP:8080/某个公开slug`。

### 4.9 宝塔日常

```bash
# 重启
# 面板 Supervisor 点重启，或：
supervisorctl restart aibot

# 更新代码（覆盖 app/、wsgi.py、requirements.txt，保留 .env 和 data/）
cd /www/wwwroot/aibot
.venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
.venv/bin/python -m flask --app wsgi init-db
supervisorctl restart aibot

# 备份（网页「设置 → 备份」也可）
.venv/bin/python -m flask --app wsgi backup-now
```

建议再加一条宝塔计划任务（每天 mysqldump）：

```bash
mysqldump -uai_bot -p'密码' --default-character-set=utf8mb4 ai_bot > /www/backup/ai_bot_$(date +%F).sql
```

## 五、普通 Linux 服务器部署

以 Ubuntu 22.04 / Debian 12 为例，无宝塔。CentOS / Rocky 把 `apt` 换成 `dnf` 即可。

### 5.1 系统包

```bash
sudo apt update
sudo apt install -y python3.11 python3.11-venv python3.11-dev \
  mysql-server nginx git build-essential pkg-config default-libmysqlclient-dev
sudo systemctl enable --now mysql nginx
```

没有 3.11 时用 3.12。然后按 [3.2](#32-命令行建库普通服务器--自装-mysql) 建库。

### 5.2 代码与依赖

```bash
sudo useradd -r -m -d /opt/aibot -s /usr/sbin/nologin aibot
sudo mkdir -p /opt/aibot/app
# 把项目文件放到 /opt/aibot（可用 git clone 或 scp）
sudo chown -R aibot:aibot /opt/aibot

sudo -u aibot -H bash -lc '
  cd /opt/aibot
  python3.11 -m venv .venv
  .venv/bin/pip install -U pip
  .venv/bin/pip install -r requirements.txt
  cp .env.example .env
'
```

编辑 `/opt/aibot/.env`：按 [4.4](#44-配置-env) 填写 MySQL、`SECRET_KEY`、`LLM_API_KEY`、`PAGE_PORT`。`SESSION_COOKIE_SECURE` 若暂无 HTTPS 设 `0`。

```bash
sudo -u aibot -H bash -lc 'cd /opt/aibot && .venv/bin/python -m flask --app wsgi init-db'
```

### 5.3 systemd 守护

`sudo tee /etc/systemd/system/aibot.service >/dev/null <<'EOF'`

```ini
[Unit]
Description=Lingxi AiBot
After=network.target mysql.service
Requires=mysql.service

[Service]
Type=simple
User=aibot
Group=aibot
WorkingDirectory=/opt/aibot
Environment=PYTHONUNBUFFERED=1
Environment=FLASK_APP=wsgi:app
ExecStart=/opt/aibot/.venv/bin/waitress-serve --host=127.0.0.1 --port=8000 --threads=8 --channel-timeout=3600 wsgi:app
Restart=on-failure
RestartSec=5
# 网页端口、图片、备份都在项目目录下，工作目录必须是项目根

[Install]
WantedBy=multi-user.target
EOF
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now aibot
sudo systemctl status aibot --no-pager
curl -I http://127.0.0.1:8000/login
```

直连公网 IP 访问后台时，把 `--host=127.0.0.1` 改成 `0.0.0.0`，并 `ufw allow 8000/tcp`。

### 5.4 防火墙与网页端口

```bash
sudo ufw allow OpenSSH
sudo ufw allow 8080/tcp          # PAGE_PORT
# 若用 Nginx HTTPS：
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

云控制台安全组要同步放行。

### 5.5 （可选）Nginx 反代 + SSE

`/etc/nginx/sites-available/aibot`：

```nginx
server {
    listen 80;
    server_name admin.example.com;   # 没有域名可写 _ 或服务器 IP

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_cache off;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_read_timeout 300s;
        client_max_body_size 20m;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/aibot /etc/nginx/sites-enabled/aibot
sudo nginx -t && sudo systemctl reload nginx
```

证书可用 certbot。启用 HTTPS 后把 `SESSION_COOKIE_SECURE=1` 并 `systemctl restart aibot`。

飞书 HTTP 回调需要这一层 HTTPS；只用 SDK 长连接则不必。

```bash
sudo systemctl restart aibot
sudo journalctl -u aibot -f
```

## 六、Docker 部署

仓库根目录的 `Dockerfile` + `docker-compose.yml`：

- 应用：`python:3.11-slim`，**gunicorn 1 worker × 8 线程**，超时 300 秒
- 可选：Caddy 自动 HTTPS（需域名；无域名时只启动 `app`，不要起 `caddy`）
- 可选：`--profile mysql` 起一个 MySQL 8 容器
- `./data` 与 `./.env` 挂进容器，安装向导改配置不会丢

先在项目根准备 `.env`（compose 的 `env_file` 要求文件必须存在）：

```bash
cp .env.example .env
# 编辑 .env：至少 MYSQL_*、SECRET_KEY、LLM_API_KEY
```

安装 Docker：

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER    # 重新登录后生效
docker compose version           # 需要 v2
```

### 6.1 容器如何连 MySQL（最容易填错）

| 你的 MySQL 在哪 | `.env` 的 `MYSQL_HOST` | 还要做什么 |
|---|---|---|
| 本机 / 宝塔 MySQL | `host.docker.internal` | MySQL 用户允许来自 Docker 网段；3306 听在 0.0.0.0 或至少 docker0 |
| compose 里的 `db` 服务 | `db` | `docker compose --profile mysql up -d` |
| 局域网另一台 | 那台的局域网 IP | 对方防火墙放行本机 IP；用户 `'ai_bot'@'%'` 或指定网段 |

**错误示范**：应用在容器里却写 `MYSQL_HOST=127.0.0.1` —— 那是容器自己，不是宿主机。

### 6.2 方式 A：只用 app 容器（接已有 MySQL）

`.env` 示例：

```ini
MYSQL_HOST=host.docker.internal
MYSQL_PORT=3306
MYSQL_USER=ai_bot
MYSQL_PASSWORD=...
MYSQL_DB=ai_bot
SESSION_COOKIE_SECURE=0
PAGE_PORT=8080
```

`docker-compose.yml` 里应用服务已准备网页端口映射，把 `PAGE_PORT` 与 compose `ports` 写成同一个值（默认示例 8080）。

无域名、不启 Caddy（推荐端口模式）：

```bash
docker compose up -d --build app
docker compose exec app python -m flask init-db
docker compose logs -f app
```

这时还要在 compose 里给 app **打开 `8000:8000`**（文件中已注释，按需取消注释），浏览器访问 `http://服务器IP:8000`。不要执行无服务名的 `docker compose up -d`，那会顺带启动 Caddy（默认配置里是示例域名，会去申请证书失败）。

### 6.3 方式 B：容器内 MySQL（推荐干净机器一条龙）

`.env`：

```ini
MYSQL_HOST=db
MYSQL_PORT=3306
MYSQL_USER=ai_bot
MYSQL_PASSWORD=应用密码
MYSQL_DB=ai_bot
MYSQL_ROOT_PASSWORD=root强密码
SESSION_COOKIE_SECURE=0
PAGE_PORT=8080
```

```bash
# 只起应用 + MySQL（不起 Caddy）
docker compose --profile mysql up -d --build app db
# 等 db 健康后再初始化（docker compose ps 里 db 为 healthy）
docker compose exec app python -m flask init-db
```

数据在 Docker 卷 `mysql_data` 里。删卷会丢库：`docker compose --profile mysql down -v` **危险**。

逻辑备份：

```bash
docker compose exec db sh -c 'mysqldump -uai_bot -p"$MYSQL_PASSWORD" --default-character-set=utf8mb4 ai_bot' > backup.sql
```

应用级备份仍走「设置 → 备份」或：

```bash
docker compose exec app python -m flask backup-now
```

文件在宿主机 `./data/backups/`。

### 6.4 方式 C：Caddy 自动 HTTPS（有域名时）

1. DNS：把后台域名（以及可选的网页域名）A 记录指到服务器
2. 编辑 `docker/Caddyfile`，把示例域名换成你的
3. `.env` 填相同的 `ADMIN_DOMAIN` / 可选 `PAGE_DOMAIN`，`SESSION_COOKIE_SECURE=1`
4. 安全组放行 80/443

```bash
docker compose up -d --build          # 起 app + caddy
# 若同时要容器 MySQL：
docker compose --profile mysql up -d --build
docker compose exec app python -m flask init-db
```

无域名时不要强行开 Caddy 的 443。可用文件顶部注释里的 `:80` 段，或干脆不启动 `caddy` 服务。

Caddy 反代 SSE 一般不用关缓冲；若对话不流式，检查是否又在前面套了一层宝塔 Nginx。

### 6.5 Docker 与网页端口

独立网页端口在 **app 容器内**监听。必须：

1. `.env` / 设置页 `PAGE_PORT=8080`
2. compose 把 `8080:8080` 映射到宿主（已按 `PAGE_PORT` 变量写好）
3. 宿主机防火墙 + 云安全组放行 8080

改端口：同时改 `.env`、compose 映射、安全组，然后 `docker compose up -d`。

### 6.6 安装向导在 Docker 里

```bash
docker compose exec app cat /app/data/setup_token.txt
```

打开 `http://IP:8000/setup`（或 Caddy 域名 `/setup`）粘贴令牌。因为 `./.env` 已挂载，向导写入的 MySQL 配置会留在宿主机。

健康检查访问容器内 `http://127.0.0.1:8000/login`。若设置了 `ADMIN_ENTRY`，`/login` 会 404，健康检查失败——把检查路径改成 `/<入口>/login`，或暂时去掉 `ADMIN_ENTRY`。

### 6.7 更新镜像

```bash
git pull
docker compose up -d --build app               # 有容器 MySQL：再加 --profile mysql 且带上 db
# docker compose --profile mysql up -d --build app db
docker compose exec app python -m flask init-db
```

不要覆盖宿主机 `.env` 和 `data/`。

## 八、常用命令

在项目根执行（Docker 则加 `docker compose exec app` 前缀）：

| 命令 | 作用 |
|---|---|

## 九、安全清单（公网）

- [ ] 管理员密码已改，不是 `admin123`
- [ ] `SECRET_KEY` 为随机长串，且备份在密码管理器里（改了所有人掉线）
- [ ] HTTP 用 `SESSION_COOKIE_SECURE=0`，HTTPS 用 `1`，不要混
- [ ] MySQL 不对公网；应用用户非 root
- [ ] 后台端口若已反代，8000 只绑 `127.0.0.1`
- [ ] 网页端口只提供公开内容，不要把后台暴露在同一端口
- [ ] 建议设置 `ADMIN_ENTRY`（改后重启；登录 URL 变成 `https://域名/<入口>/login`；飞书回调不受影响）
- [ ] App Token 用设置页按用户生成，`.env` 的 `API_TOKEN` 仅作可选回退
- [ ] 「设置 → 备份」打开每日备份，定期把 `data/backups/` 拷走；重要数据另做 mysqldump
- [ ] 技能启用前人工看代码；公开网页/图片前确认没有密钥

## 十、常见问题

| 现象 | 原因与处理 |
|---|---|
| `Flask.__call__() missing start_response` | 用了 uvicorn → 换 waitress / gunicorn |
| 提醒、早报发两遍 | 多个 worker 或多个容器 → 只留一个进程 |
| AI 回复不流式 | 反代缓冲 → [1.7](#17-反代必须关掉-sse-缓冲) |
| 登录后立刻掉线 | `SESSION_COOKIE_SECURE=1` + HTTP → 改 `0` 或上 HTTPS |
| 500 / 安装向导停在① | MySQL 连不上 → [3.5](#35-连不上时对照错误码) |
| Docker 里 2003 | `MYSQL_HOST` 写成了 `127.0.0.1` → 改 `db` 或 `host.docker.internal` |
| compose 报 `.env` 是目录 | 忘了先 `cp .env.example .env`，Docker 把挂载点建成了目录 → 删掉该目录再复制文件 |
| 网页端口访问拒绝 | 安全组/防火墙没放行；或端口与后台冲突；看日志是否「已监听」 |
| 飞书收得到消息但卡片/链接打不开 | 没有公网 IPv4，或 `PAGE_PORT` 未映射到宿主 |
| SDK 与回调各收一次 | 两种模式同时开 → 设置里只留一种并重启 |
| 健康检查失败 | 配置了 `ADMIN_ENTRY`，`/login` 变成 404 |
| 429 登录频繁 | 限流 10 次/分钟，等一分钟 |
| 提示请使用后台域名 | `ADMIN_DOMAIN` 与浏览器地址不一致，或反代没传 `Host` |
| 更新后缺表缺列 | 再跑 `flask init-db` |
| 重建 Docker 后数据库配置丢失 | 没挂载 `./.env`（本仓库 compose 已挂） |
