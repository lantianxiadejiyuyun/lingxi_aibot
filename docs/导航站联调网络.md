# 导航站与灵犀的联调网络

导航站采用独立 SSH 反向隧道接入灵犀后台，保留原有 GOST 公开网页映射。接口字段见 [接入 API](接入API.md)。

## 链路与地址

```text
浏览器 → 导航站 HTTPS/WSS → 导航站 Node 后端
       → 云端 127.0.0.1:18000 → SSH 反向隧道
       → fnOS 127.0.0.1:8000 → 灵犀 /lingxi/api/v1
```

2026-10-03，导航站部署端已完成上述 SSH 隧道配置；API 路由随本版本灵犀镜像发布。隧道和导航站 HTTPS 代理由导航站侧管理。

| 用途 | 地址 |
|---|---|
| 局域网 API | `http://192.168.100.72:8000/lingxi/api/v1` |
| 云端 Node 内部 API | `http://127.0.0.1:18000/lingxi/api/v1` |
| 云端 Node 内部 WebSocket | `ws://127.0.0.1:18000/lingxi/api/v1/ws` |
| 导航站 HTTPS 绑定根地址 | `https://index.eugenstudio.cn/lingxi-service` 或 `https://ojjlab.eugenstudio.cn/lingxi-service`，代理发布后可用 |
| 原有公开网页 | 云 `30079` → fnOS `8080`；保留原 GOST 配置 |

每位导航站用户绑定自己的灵犀 API Token，由 Node 服务端保存并代理请求。浏览器不直接访问云端回环端口，也不持有灵犀 Token。

## HTTPS 代理约定

仅代理 `/lingxi-service/api/v1/`，将其改写为上游 `/lingxi/api/v1/`。不要将整个后台页面目录公开。下面是配置示例，实际配置由导航站维护：

```nginx
location ^~ /lingxi-service/api/v1/ {
    proxy_pass http://127.0.0.1:18000/lingxi/api/v1/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 600s;
}
```

外部账号接口为 `/lingxi-service/api/v1/me`，WebSocket 为 `/lingxi-service/api/v1/ws`。`/me.websocket_path` 返回的是灵犀内部入口，客户端应从绑定根地址构造外部 WS 地址。

SSH 隧道应仅监听云端 `127.0.0.1:18000`，由专用账号、密钥和服务管理器维护掉线重连；不对公网放行 18000。不要复用 40030：已有 `botadmin.eugenstudio.cn` 配置指向它，启用该端口会影响另一个后台入口。

## 发布与验证

1. 备份灵犀数据库、代码和旧镜像，只重建应用容器；保留数据库、GOST 和现有端口。
2. 在 fnOS 检查 `/healthz` 返回 200，`/lingxi/api/v1/me` 无 Token 返回 401。
3. 从云端隧道及导航站 HTTPS 入口重复账号检查，确认回环监听且公网 18000 不可直连。
4. 使用临时测试账号验证日程、待办、聊天历史，以及 SSE 和 WebSocket 的 `/help` 回复；验证完成后清理测试数据。
5. 复查原有公开网页、飞书连接和会话模型选择。

应用回退使用部署备份中的旧镜像和代码。网络回退只撤销新增的 API 代理与 SSH 隧道，不修改原 30079 公开网页映射。
