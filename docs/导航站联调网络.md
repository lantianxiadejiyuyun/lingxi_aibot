# 导航站与灵犀的联调网络

导航站通过云端回环地址接入 GOST，再转发至灵犀后台；原有 GOST 公开网页映射继续使用。接口字段见 [接入 API](接入API.md)。

## 链路与地址

```text
浏览器 → 导航站 HTTPS/WSS → Nginx API 代理
       → 云端 127.0.0.1:62919 → GOST
       → fnOS 127.0.0.1:8000 → 灵犀 /lingxi/api/v1
```

2026-10-03，灵犀镜像和两个导航站的 HTTPS/WSS 代理上线，当时通过云端 `127.0.0.1:18000` 的 SSH 反向隧道接入。

2026-10-08 检查时，fnOS 局域网地址为 `192.168.100.17`。原 SSH 隧道的 `18000` 已无监听，两站 Nginx 的 API 上游改为现有 GOST 的 `127.0.0.1:62919`，配置检查及重载通过。云端回环探测 `/healthz` 返回 200、`/lingxi/api/v1/me` 无 Token 返回 401；HTTPS 路径限制及 WebSocket、SSE 代理配置保持不变。

本次外部验证：两站 HTTPS `/lingxi-service/api/v1/me` 返回 401，`/lingxi-service/login` 返回 404；WSS 升级成功，并正确拒绝无效 Token。该检查验证了代理连通和认证边界，未重新执行已登录账号的聊天、日程或待办业务测试。

| 用途 | 地址 |
|---|---|
| 局域网 API | `http://192.168.100.17:8000/lingxi/api/v1` |
| 云端代理内部 API | `http://127.0.0.1:62919/lingxi/api/v1` |
| 云端代理内部 WebSocket | `ws://127.0.0.1:62919/lingxi/api/v1/ws` |
| 导航站 HTTPS 绑定根地址 | `https://index.eugenstudio.cn/lingxi-service` 或 `https://ojjlab.eugenstudio.cn/lingxi-service` |
| GOST 后台映射 | 云 `62919` → ASUS-Server `127.0.0.1:8000` |
| 原有公开网页 | 云 `30079` → fnOS `8080`；保留原 GOST 配置 |

每位导航站用户绑定自己的灵犀 API Token，由 Node 服务端保存并代理请求。浏览器不直接访问云端回环端口，也不持有灵犀 Token。

2026-10-03 上线验证：两站 `/api/v1/me` 无 Token 返回 401，管理页面子路径返回 404，WSS 可升级并拒绝无效 Token；fnOS 容器解析两站 DNS 均为公网地址，HTTPS 保险库回调无 Token 返回 401。Gunicorn 的有效测试账号已完成 SSE/WS `/help`、历史保存及清理，未调用付费模型或读取真实保险库。这些是当时的验证记录，后续变更按下方项目复查。

## HTTPS 代理约定

仅代理 `/lingxi-service/api/v1/`，将其改写为上游 `/lingxi/api/v1/`。不要将整个后台页面目录公开。下面是配置示例，实际配置由导航站维护：

```nginx
location ^~ /lingxi-service/api/v1/ {
    proxy_pass http://127.0.0.1:62919/lingxi/api/v1/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 600s;
}
```

外部账号接口为 `/lingxi-service/api/v1/me`，WebSocket 为 `/lingxi-service/api/v1/ws`。`/me.websocket_path` 返回的是灵犀内部入口，客户端应从绑定根地址构造外部 WS 地址。

导航站代理使用云端回环 `127.0.0.1:62919`。公网 `47.105.106.206:62919` 的直接访问与这条回环链路分别验收：公网端口不可达，不等于云端代理上游不可达。GOST 客户端采用 host 网络时，目标 `127.0.0.1:8000` 指向 fnOS 宿主机；应用需保留该回环端口发布。

当前链路不依赖 SSH `18000`，无需为恢复 API 对公网开放它。不要复用 40030：已有 `botadmin.eugenstudio.cn` 配置指向它，启用该端口会影响另一个后台入口。

## 发布与验证

1. 备份灵犀数据库、代码和旧镜像，只重建应用容器；保留数据库、GOST 和现有端口。
2. 在 fnOS 检查 `/healthz` 返回 200，`/lingxi/api/v1/me` 无 Token 返回 401。
3. 分别从云端 `127.0.0.1:62919` 和两个导航站 HTTPS 入口检查 `/lingxi/api/v1/me`、`/lingxi-service/api/v1/me`，无 Token 均应返回 401；导航站管理页面子路径仍应返回 404。
4. 使用临时测试账号验证日程、待办、聊天历史，以及 SSE 和 WebSocket 的 `/help` 回复；验证完成后清理测试数据。
5. 单独检查公网 `47.105.106.206:62919` 的 TCP／HTTP 可达性，以及 `30079` 的原有公开网页；不要用其中一项代替云端回环及导航站 API 检查。复查飞书连接和会话模型选择。

应用回退使用部署备份中的旧镜像和代码。网络回退使用已验证可用的上游；只有原 SSH 隧道恢复并通过检查后，才能改回 `18000`。保留 API 路径限制，不修改原 `30079` 公开网页映射。
