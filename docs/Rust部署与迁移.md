# v2 部署、QQ 接入与迁移

## 全新安装

Linux / WSL 推荐使用统一入口，自动生成服务密钥和 NapCat 初始配置：

```sh
bash scripts/deploy.sh init --username admin
bash scripts/deploy.sh up
bash scripts/deploy.sh status
```

需要局域网访问时在首次 `init` 加 `--host 你的局域网IP`。已有 `.env` 时脚本不会覆盖；使用 `up` 启动已有部署。`backup` 会短暂停止写入，备份应用、QQ 登录及向量数据并恢复服务。飞牛预构建镜像流程见 [fnOS 部署](fnOS部署.md)。

手动部署也可继续使用以下命令。先配置 `.env.docker.example` 中的地址和随机密钥；外部 NapCat 用户将 `COMPOSE_PROFILES` 留空、`LINGXI_NAPCAT_MANAGED=false`。

```sh
docker compose -f docker-compose.yml build app
# 在当前终端设置一个至少12字符的强密码，不写入镜像。
export LINGXI_ADMIN_PASSWORD='替换为你的强密码'
docker compose -f docker-compose.yml run --rm -e LINGXI_ADMIN_PASSWORD app init --username admin
unset LINGXI_ADMIN_PASSWORD
docker compose -f docker-compose.yml up -d --wait
```

PowerShell 对应的环境变量命令是 `$env:LINGXI_ADMIN_PASSWORD='你的强密码'`，使用后 `Remove-Item Env:LINGXI_ADMIN_PASSWORD`。

打开 `http://127.0.0.1:8000`，登录后在「设置 → 对话模型」配置服务地址、协议、模型 ID、密钥和真实上下文容量。API Base URL 包含 `/v1` 等服务前缀。

默认仅绑定本机。需要局域网访问时同步设置 `LINGXI_BIND_HOST`、`LINGXI_PUBLIC_URL`、`NAPCAT_BIND_IP` 与 `LINGXI_NAPCAT_WEBUI_URL`；公网部署应通过 HTTPS 反向代理，并为管理入口设置访问限制。运行数据保存在独立命名卷 `lingxi_rust_data`，不会复用 v1 MySQL 卷。首次切换可设置 `LINGXI_PORT=8001` 与旧版并行检查。

Compose 从根目录 `.env` 读取端口等变量，可复制 `.env.docker.example` 后修改。原生 Rust 进程不自动加载 `.env`，需通过终端或进程管理器传入 `.env.example` 中的环境变量。模型、通知和 QQ 的密钥在登录后的设置页保存。旧版的 `MYSQL_*`、`SECRET_KEY`、`FLASK_*` 配置不适用于 v2。

默认服务内置 Worker 和飞书官方 SDK 管理器。开启飞书私聊后自动建立长连接，不需要另外创建桥接 Token 或容器。可用 `serve --no-worker` 和单独的 `worker` 命令拆分任务执行；Compose 提供 `worker` profile，多个 Worker 使用同一本地 SQLite 的租约领取任务，独立 Worker 不启动飞书 SDK。

## QQ 群与主人记忆

1. 管理员在 QQ 页一键登录统一部署的 NapCat 管理界面，无需从日志复制登录密钥，再扫码登录机器人 QQ；也可使用已有 NapCat 或其他 OneBot v11 实现。Compose 将 NapCat 的 `config` 目录只读挂载到应用，后台使用当前 WebUI 密钥向 NapCat 换取标准会话，长期密钥留在服务端，浏览器 URL 不携带任何凭据。保留源码中的 `integrations/napcat-webui-handoff/` 目录：它会只读挂载到 NapCat，负责建立浏览器会话。NapCat 本身仍要求认证，外部 NapCat 保留普通管理地址入口。启用正向 HTTP API 和 HTTP 客户端事件上报。新部署脚本会创建 HTTP API 初始配置，回调仍按下面步骤配置。
2. 专用向量库随默认 Compose 启动，不向宿主机发布端口，容器内地址为 `http://qdrant:6333`。`LINGXI_QDRANT_API_KEY` 使用部署生成的随机密钥。
3. 统一 Compose 默认开启 `LINGXI_ALLOW_PRIVATE_NETWORK=true`，使应用可访问容器内的 NapCat、Qdrant 和嵌入服务。此选项允许已认证用户配置内网服务地址，仅用于可信用户环境；原生 Rust 默认仍关闭。
4. 进入「QQ 群与会话」，逐个添加群号。每个群对应一个固定会话，可设置群名称、模型、群人设和独立开关；再到「接入设置」填写共用的主人 QQ、机器人 QQ、默认模型、OneBot HTTP 地址、专用 Qdrant 地址及嵌入模型接口。

旧群白名单会自动获得独立会话。移除群停止接收和回复，不删除历史；重新添加同一群会沿用会话 ID。群会话页显示最近 100 条群消息，主人发言从主库读取、成员发言从独立群库读取。同群消息串行处理，已发送的机器人回复进入后续上下文，各群不混用历史或私人记忆。
5. 首次保存前复制回调密钥。在 NapCat 的 HTTP 客户端中，把该页面给出的 `/api/v2/qq/inbound/账户ID` 作为上报地址，在 Token 字段填入回调密钥原文（不加 `Bearer`），消息格式选择 `array`；NapCat 自动携带 `X-Signature: sha1=…`，后端按原始请求体验证 HMAC-SHA1。其他 OneBot 客户端仍可设置 `Authorization: Bearer 回调密钥`。它是专用回调密钥，与灵犀登录 Token、OneBot 访问 Token 分开。
6. 启用接入。接收群内文字消息；被 `@` 时回复。每群回复最短间隔 5 秒，不处理自身消息或非白名单群。

主人号一旦绑定不能直接换号，避免既有人物数据归错人。姓名、群名片或“我是主人”等文本不会改变身份判断。

人物提取按消息批次执行（至少三条本人发言，约每八条或被提及时调度），支持手动补充、修正、忘记和语义查找。主人的对话及机器人回复写入主库的专属会话，自动提取的性格偏好默认长期保留；其他人的原文写入独立元数据库，特点写入该库和专用 Qdrant，默认有效期 180 天。群成员原始消息默认保留 30 天，可配置为 1–365 天，不会清理主人的主库记录。模型调用需要用户自己的服务凭据，会消耗对应服务额度。

此版本实现 HTTP 事件上报与正向 HTTP 回复，尚未实现 NapCat 反向 WebSocket 和扫码登录管理。图片、语音、视频消息不做人物特征提取。实际 QQ 登录和网络连通性需要在自己的 NapCat 环境配置后验证。

更换嵌入模型会生成新的集合，随后点击「重新同步向量」。旧集合和旧 Qdrant 实例的备份不自动删除，迁移完成后需单独按保留策略清理；应用只查询当前配置对应的集合。

## QQ 图片与表情收藏

QQ 主人私聊支持纯图、图文和图片表情：先验证、下载图片，再将受限预览交给看图模型，识别说明与文字一起进入主人的会话。看图模型默认沿用 QQ 对话模型，也可在「图片与表情 → 收藏偏好」指定。需要支持图片输入；失败时明确告知，不猜测图片内容。

图片收藏默认关闭，可在上述页面开启。范围包括绑定主人的私聊和 QQ 群白名单，忽略机器人自己的消息；关闭收藏不影响私聊识图。可以选择两种方式：

- **模型挑选 + 主人命令**：把图片缩略预览发送给所选看图模型，由模型根据画面和配置的审美偏好决定是否喜欢。只有明确选择且置信度达到 0.75 才保存，并记录标题、标签、视觉理由；拒绝或低置信度结果不保存图片。选择支持图片输入的模型，可独立于 QQ 对话模型配置，兼容 OpenAI Chat Completions 和 Anthropic Messages 格式。
- **仅主人命令**：绑定的主人 QQ 在同一条消息中附图并说「收藏这张图」，或回复当前私聊 / 群聊的一张图片并说这句话，即直接保存，不经过模型筛选。也支持「收藏这个表情包」和 `/收藏`。引用图片需要 OneBot 的 `get_msg` 接口。其他成员说同样的话不能绕过模型判断。

开启收藏需要先完成 QQ 接入。如果只使用主人命令，可在 QQ 接入设置中关闭人物记忆和被提及回复，此时无需模型和向量库。命令结果在收藏页的「最近的收藏判断」查看，当前不会额外发送群消息确认。

支持 PNG、JPEG、GIF、WebP；每条消息最多处理 4 张。静态原图不超过 32 MiB、3600 万像素，长宽均不超过 16384，解码分配预算为 192 MiB。模型接收最长边 1024 像素、单张不超过 384 KiB 的压缩图：较大的不透明图片使用 JPEG，透明图与小图使用 PNG；超出字节预算时继续降质或缩小。页面缩略图最长边 512 像素，收藏、下载与回发保留原文件。GIF 原文件仍不超过 8 MiB、1600 万像素、单边 8192，模型接收沿动画抽取的最多 10 帧及时间顺序，每帧压缩 PNG 不超过 384 KiB；不足 10 帧读取全部帧，只依据采样内容理解动作。GIF 单轮最多 1000 帧、10 分钟，总解码像素不超过 1.6 亿，抽帧处理预算为 10 秒；超限提示缩小或缩短动图，不静默退回首帧。图片加载失败会区分下载 HTTP 状态、原图大小、格式与解码阶段，不向模型或聊天记录暴露原始签名下载地址。暂不收集 QQ 内置表情 ID、闪照、合并转发中的图片。无图片也无引用的独立「收藏」消息不会自动猜测前一张图。

自动收藏判断默认每库每小时最多查看 20 张，可调整到 1–200 张；主人命令不占看图额度。相同文件按内容哈希去重，24 小时内被拒绝的同图不再重复询问模型。每库默认最多 500 张、256 MiB，容量统计包含原图和预览，不包含 SQLite、索引与日志开销。达到容量上限后需清理或调高上限。

收藏页支持预览原图和动图、按名称/标签/理由搜索、标记特别喜欢、修改名称标签、下载、删除以及重试失败任务。删除后不会被模型自动再次收集；主人再次明确命令可以重新保存。模型判定依赖所选视觉模型的能力；测试使用本地模拟接口验证实际图片载荷和处理流程，真实 QQ 与模型仍需部署后联调。

主人的私聊附件及收藏在主库，群收藏在独立的 `qq/people.sqlite3`，各库独立去重和计算容量。私聊附件的来源及原图加密归档，原图密文预算为每账号 256 MiB；超过后仍可识图，但只保留来源与说明。图片说明不用于自动人设养成，私聊的长期记忆提取只读取主人的原始文字，图片内容不直接写入人物向量库。未完成收藏的来源地址加密保存，任务参数仅保存记录 ID 和范围。删除收藏会清除图库原图和预览、释放逻辑额度，不删除独立聊天附件归档；数据库文件大小不立即缩小，备份按原有策略处理。

开启收藏后，QQ 回复可由模型从当前会话的收藏中选至多一张图片。主人私聊只能访问私人图库，群聊只能访问当前群图库；模型不能指定任意 URL、文件路径或接收人。选图失败或超时仍发送文字，结果不确定时不会自动重发图片。

## 主动陪伴与私聊连接

侧栏「主动陪伴」对应 `/#/companion`，默认关闭。先配置对话模型，再选择陪伴模型、时段、兴趣及推送渠道，保存后约 15 分钟开始检查，不会立即发消息。需要运行内置或独立 Worker。

- 时间按账号时区计算。活动开始和结束相同表示全天，免打扰开始和结束相同表示关闭；支持跨午夜时段。日程正在进行时暂缓，识别每日、每周、每月重复规则，全天日程不阻塞一整天。
- 默认每天最多 3 条、至少间隔 180 分钟、刚聊过后安静 45 分钟。这些是上限，模型可以选择不发送；连续两次主动分享后没有互动会至少等待 24 小时，四次后至少等待 72 小时。
- 模型沿用所选人设，参考账号主库记忆、近两周的近期对话、未完成待办与已有分享，不读取其他账号或群成员独立记忆。判断失败不会编造消息；每天最多进行 24 次模型判断，判断间隔至少 30 分钟。
- 兴趣最多 8 项，每项 40 字。开启 B 站分享后还需配置搜索服务；仅从实际搜索结果选择有效 B 站视频链接，使用标题与摘要，不声称看完视频。
- 「最近的小记」显示判断、分享内容和每个渠道的投递结果。成功消息同时保存到主库「灵犀日常」会话。配置保存、关闭陪伴、解绑都会取消对应待发消息；已经发出的网络请求无法撤回。

站内通知无需配置。飞书自定义机器人（可选签名）、飞书应用机器人（App ID / Secret、接收人类型与 ID）、Server酱（Turbo 或 Server酱³ SendKey）在「设置 → 通知渠道」配置。密钥加密保存，页面只显示掩码；保存渠道不发送测试消息。此处渠道选择目前用于主动陪伴，其他任务的站内提醒保持各自流程。

**个人 QQ**：在陪伴页点击「配置 NapCat」，填写绑定的主人 QQ、机器人 QQ、OneBot HTTP 地址与 Token、事件回调密钥并开启私聊。按照页面回调地址配置 NapCat 的 HTTP 客户端，在 Token 字段填回调密钥原文。私聊只接受绑定主人，使用主库对话、记忆和个人工具；无需启用群功能或 Qdrant。主人身份、连接和回调密钥与群接入共用，内网服务仍需 `LINGXI_ALLOW_PRIVATE_NETWORK=true`。QQ 文字回复与主动消息通过 `send_private_msg` 发送。

**AstrBot**：安装 `integrations/astrbot` 插件，私聊 `/lingxi 身份`，将返回的标识、v2 API 基地址和账号 Token 填入插件后台，再在同一私聊 `/lingxi 绑定`。回到陪伴页选择 AstrBot。Compose 覆盖文件为 `docker-compose.astrbot.yml`，完整部署步骤见 [插件说明](../integrations/astrbot/README.md)。

消息先登记投递意图再发送；发送超时或进程中断时标记「结果待核实」，不会自动重发以免重复打扰。AstrBot 领取后不再重复发放，插件持久保存确认信息，确认丢失时只重试确认。待发消息到用户当地午夜过期，不在次日补发。外部平台投递与本地写入不能形成同一事务，因此无法保证外部消息严格只送达一次。

本地模拟测试覆盖并发去重、关闭后的取消、时区与重复日程、限额、模型保持安静、实际搜索链接、渠道失败、QQ 主人私聊及 AstrBot 领取确认。真实模型、QQ、飞书和 Server酱需配置自己的凭据后联调。

## 备份与恢复

```sh
docker compose -f docker-compose.yml exec app lingxi backup /data/backup-2026-10-21.sqlite3
```

同时生成主库快照，以及存在群成员库时的 `backup-2026-10-21.sqlite3.qq.sqlite3`。两个库分别生成一致快照；需要同一业务时间点时先停止写入和 Worker。另行安全备份 `master.key`、`assets/` 和 Qdrant 存储卷或集合快照。没有 `master.key` 无法解密已保存的接入配置。

恢复时停止进程，把主库恢复为 `lingxi.sqlite3`、群成员库恢复为 `qq/people.sqlite3`，还原密钥和资源后启动。向量可以从群成员元数据重新生成，但会产生嵌入服务调用。不要使用 `docker compose down -v` 作为升级步骤，它会删除数据卷。

## v1 数据导入

迁移前先保留完整 v1 数据库、配置和文件备份，并停止旧版写入。导出脚本只执行读取，不修改原数据库。导出文件包含敏感数据，应只保存在受控目录，用后删除。

```sh
# 在能够访问旧数据库的 Python 环境中安装独立的导出依赖。
python -m pip install -r scripts/requirements-migration.txt
export LINGXI_LEGACY_DATABASE_URL='mysql+pymysql://用户:密码@地址/数据库?charset=utf8mb4'
python scripts/export_legacy.py --output legacy-export.json
```

先检查导出脚本 `--help` 的路径参数；导入时把文件只读挂载到空的 v2 数据目录，设置 `LINGXI_IMPORT_PASSWORD`，执行 `lingxi import /路径/legacy-export.json`。禁止把全新管理员初始化和导入同时用于同一个目标库。导入事务失败会整体回滚。

导入保留业务记录、会话、消息、摘要边界、长期记忆和通知，并将全部旧表原始行加密归档。首个启用用户使用新的迁移密码，其他用户默认停用，管理员使用 `reset-password --username 用户名` 激活并重设密码。旧页面默认私有、旧技能默认停用。图片原始文件需另行迁移，模型、外部接入、存储和定时计划需重新配置；仅归档的旧设置不会被自动执行。

## 人设养成

「人设养成」为每个账号、每份模型人设保存独立的成长层，不自动修改模型设置中的核心人设。默认不自动学习；开启后，只观察新完成的网页聊天、绑定主人 QQ 私聊和 AstrBot 私聊。群聊及后台调查不会进入养成素材，也不会读取这份私人养成。

自动整理需积累至少 6 次成功对话，两次尝试至少间隔 2 小时。一次选取最多 24 条待整理原话，每批最多 6 条、产生最多 2 个变化，总计最多保留 24 个条目。按模型配置的最大输出预算处理；材料超出上下文或输出被截断时缩小批次，最多尝试 8 批，整次任务最长 8 分钟。每批成功后独立保存并推进进度，后续失败不撤销已完成批次，也不跳过未完成片段。整理期间新到的片段留待下次。

养成页面提供「立即整理」，有新片段即可手动提交，不受 6 次对话和 2 小时间隔限制；仍须开启该人设养成和个人会话养成权限。同一人设已有任务排队或运行时复用任务，页面自动更新处理状态。手动任务也受分批数量与时间预算限制，剩余片段可以稍后再次整理。「设置中心 → 模型与人设」提供上下文容量与最大输出的独立常用值，并允许自定义。上下文容量不会扩大模型服务自身的限制；输出截断应检查最大输出，推理内容也可能计入该额度。

仅提炼性格细节、专属称呼、相处习惯、共同兴趣和共同回忆；性格细节需要当前批次中至少两条不同主人消息的明确反馈。模型可以返回空数组。所有自动变化须附真实消息 ID 和逐字原话；助手自己生成的说法不能充当经历证据。格式错误、引用无效、暂停学习或整理途中改动条目时，未提交的批次保留待处理状态。

已保存成长以受限参考数据注入同一人设的私聊、私人延迟补充和主动陪伴；当前用户要求和核心设定优先。页面支持查看来源、手动添加和修改、固定条目及删除。固定条目不被自动覆盖；删除留下同分类同名称的阻止记录，手动添加可恢复。暂停仅停止新学习，已有条目仍会生效，可分别删除。删除原会话会移除待整理素材，已经形成的成长仍需在养成页独立整理。

成长、来源引用和观察游标都位于主库 `persona_growth` / `persona_traits` / `persona_observations`，随主库一起备份；没有额外模型服务或向量库。测试使用本机模拟模型，覆盖证据验证、手动固定、暂停期间的取消、重放去重、账号及人设隔离。实际提炼质量取决于所选聊天模型。

## 与 v1 的功能差异

### QQ 聊天节奏与主动开场

「QQ 群与会话」中每个群的「聊天节奏」分别管理分条回复、延迟补充和主动开场；主人私聊在「私聊节奏」中管理前两项，在「主动陪伴」中选择 QQ 个人号渠道并开启主动会话。这些开关默认关闭，保存配置不会立即发送消息。

- 连续消息：QQ 主人私聊和每个群各自等待 5 秒安静窗口，新消息会重新计时，最多等 20 秒后打包交给模型。文字和图片保留原有顺序，超出单批预算的消息留待下一批；不同群与私聊相互隔离。
- 分条回复：模型用自然段表达多个完整意思时，按顺序分成最多 2–4 条，每段间随机等待 1–3 秒，QQ 与飞书共用此节奏。简单回答仍可只有一条；代码块保持完整，超出条数的内容合并到最后一条。QQ 收到新输入会取消旧回复尚未发出的段落，历史只记实际发出的文字。是否 @ 发言者遵守各群开关，开启时仅在第一段添加。原有 API 的 interval_secs 字段保留兼容，实际段间节奏统一使用随机 1–3 秒。
- 延迟补充：等待 1–60 分钟后由原聊天模型决定是否还想说。返回 `skip` 就结束本轮；`send` 后仅当 `continue=true` 才安排下一次判断，下一次仍可选择结束。每轮上限 1–5 次、滚动 24 小时上限 1–12 次，次数是上限，不是配额。收到新发言、修改聊天节奏或接入配置、暂停会话时取消后续发送。补充不会调用工具。
- 群主动开场：每 15 分钟检查一次，遵守账号时区、活动与免打扰时段、群安静时长、两次间隔和每日上限。只参考本群近 24 小时公开上下文与配置话题；没有近期互动、上次主动消息没人接话、没有新内容时保持安静。各群模型和人设独立，不读取主人私聊或主库记忆。
- 主人补充仍存主库，遵守主动陪伴设置中的活动时段、免打扰和忙碌日程；它与主动开启新话题的总开关独立。群开场和群补充放在独立 QQ 库，活动及分条投递记录保留 30 天。
- 分条逐条记录 pending/sending/sent/unknown/cancelled。发送失败、中断或结果不确定时停止剩余消息，不自动补发；群会话页显示每条状态，补充与开场另有活动记录。测试使用本机模拟模型和 OneBot，不向真实 QQ 发测试消息。
