## 2026-10-01

本次更新增加会话内模型控制、上下文压缩和生成网页的公网地址配置，并修复飞书长连接、日程提醒、Docker 配置持久化及前端交互问题。

### 模型与思考等级

- 在「设置 → 模型与人设」配置候选模型，每行一个模型 ID；候选项共用当前用户的接口地址、协议和 API Key。
- 网页聊天增加模型选择、思考等级、AI 自主切换及上下文状态控件。所有调整仅影响当前会话，不改其他会话或用户的默认设置。
- 新会话默认允许 AI 自主切换；AI 可在候选模型和支持的思考等级中选择，同一轮的下一次模型请求即生效。每轮限制切换次数，避免反复切换。
- 手动选择模型或思考等级后锁定选择，使用 `/auto on` 可恢复自主切换。
- 思考参数按协议、接口地址和模型能力适配；无法识别的网关仅保留 `default`。具体可选等级以界面或 `/think` 返回结果为准。

网页与飞书使用同一套命令处理逻辑；查看状态及切换配置无需调用模型，压缩需要可用模型。

| 命令 | 功能 |
|---|---|
| `/` 或 `/help` | 显示帮助 |
| `/model` | 查看当前模型与候选列表 |
| `/model 2` 或 `/model 模型ID` | 切换当前会话模型 |
| `/think` 或 `/think high` | 查看或调整支持的思考等级 |
| `/auto on`、`/auto off` | 开关 AI 自主切换 |
| `/context` 或 `/status` | 查看模型、摘要与活跃上下文状态 |
| `/compact` | 压缩较早上下文并保留完整聊天记录 |

### 保留聊天记录的上下文压缩

- 将历史摘要、已总结消息的边界和近期原文结合使用。旧消息保留在数据库中，不再因定时梳理而删除。
- 普通聊天达到 24 条活跃消息或 16000 字符，且存在可压缩的较早轮次时自动压缩；也可使用网页按钮、`/compact` 或 AI 工具触发。
- 保留最近至少 8 条用户 / 助手消息，并按完整用户轮次划分。长原文分块总结，后续压缩合并旧摘要。
- 摘要长度受被替换内容大小约束；生成失败、保存失败或摘要未有效缩短时，保留原摘要及原上下文。
- 网页、飞书和定时梳理共用会话锁，避免并发压缩或发送时混用摘要与消息边界。

上下文用量是字符估算，未计入系统提示和工具定义。摘要属于有损压缩，原文仍可在聊天记录中查看；升级前被旧版本删除的历史无法由本功能恢复。

### 生成网页默认使用公网地址

- 管理员可在「设置 → 网页站点 → 公网访问地址」填写完整 HTTP(S) 根地址，也可配置 `PAGE_PUBLIC_BASE_URL`。
- AI 创建、修改、复制、查询公开网页时返回统一公网链接，后台分享链接与公开图片地址也使用该根地址。
- 只接受协议、主机及可选端口，不接受账号密码、页面路径、查询参数或片段；私有网页和图片仍使用登录后的访问入口。
- 公网地址与内部 `PAGE_PORT` 分开配置。例如内部监听 `8080`，公网可以是另一转发端口或 `https://pages.example.com`。
- 仅更新公网地址时无需重启独立网页监听；同时修复网页地址诊断递归以及复制网页工具缺少用户作用域的问题。

此功能负责生成链接。公网端口转发、反向代理及防火墙仍需在部署环境配置，详见 [部署说明](部署.md#15-公开网页只开端口不必配证书)。

### 飞书连接与回复

- 长连接使用独立事件循环；停止或重连时先取消旧任务、关闭连接并等待线程退出，再建立新连接，避免重复连接和事件循环复用导致回复中断。
- 连接状态读取加锁；旧连接未及时结束时返回明确状态，防止同时启动第二个客户端。
- 飞书消息接入会话控制命令，与网页端共享模型选择、思考等级和压缩逻辑。

机器人仍需配置应用凭据、接收方式、消息订阅与权限，并绑定发送者账号。飞书开放平台的权限开通和应用发布属于部署操作，不会随拉取仓库自动完成。

### Docker 与 GOST 部署

仓库中的 Docker 改动：

- 用持久化目录中的 `data/.env` 保存运行配置；首次从根 `.env` 导入，安装向导可以原子保存配置，重建容器后保留。
- 独立网页在容器中默认监听 `0.0.0.0`，端口仍需由实际 Compose 配置显式发布。
- 健康检查使用 `/healthz`，配置后台入口前缀后仍可检查。
- 保持单 worker 和独立 MySQL 数据卷，提供幂等初始化及升级步骤。

GOST 的修复需要调整部署机器上的网络配置：Linux 下 `network_mode: host` 的 GOST 共享宿主机网络；若应用端口只发布到局域网 IP，通过 `127.0.0.1` 访问会失败。应按需补充 IPv4 / IPv6 回环映射，并将转发目标设为实际可访问的地址。`localhost` 可能优先解析为 `::1`，因此也要验证 IPv6 或明确使用 `127.0.0.1`。

上述宿主机地址、端口绑定和 GOST 规则属于环境配置，仓库提供通用示例，不写入特定机器的部署参数。配置片段与验证步骤见 [Docker 与网页端口](部署.md#65-docker-与网页端口)。
